qmutfind

Find the mutations in one fungal genome sample.

Style

To quickly map sequencing reads, identify mutations try qmutfind. Will identify SNPs and small insertions and deletions, describes mutational impact, and presents a locus view graphic of the variant.

It runs in this page. The page does not send your files to any server. Use it for haploid samples, such as fungal isolates or evolved strains, compared with a reference genome.

  1. Reference genome. Choose where it comes from: the NCBI list, files from your computer, or web addresses.
  2. Sample set. Add one or more samples. Each has a name and one or more reads files, from SRA, web addresses or your computer. Run them one after the other and, if you like, combine them against a parent sample.
  3. Results. Pick a sample, count its variants, plot where they are, add gene effects and draw a locus.

A sample is a name and one or more reads files. Use + to add a sample and − to remove one. Each sample takes its reads from one source: an SRA run accession, https addresses (one per line), or files from your computer (select several if the sample has more than one). The page maps every file as separate reads; it does not use read pairs. The samples run one after the other, each in its own worker. Files from your computer are read from disk and are not sent anywhere.

Limits and risks of loading reads from the web
  • Only https addresses are accepted, and addresses with a user name or password are refused. A Dropbox share link is changed to its direct address.
  • A download is limited to 2 GB. The whole file is held in memory (and a large one takes minutes), so a big run can slow or stop your browser tab. With a read limit, the page stops downloading after that many reads per file and keeps only those reads, so a bigger file is allowed. The first reads of a file are not a random sample.
  • The page checks the file size, and for an SRA run the read count, against ENA's record. It does not check ENA's MD5 sums.
  • The accession you give is sent to ENA, and the files come from the data server. Nothing is sent to this site. Only servers that allow downloads from web pages work (NCBI and ENA do).
  • Do not load private, patient or access-controlled data. The page is not a clinical tool.

How the combined table is made, and its limits
  • One row per variant (same contig, position, REF and ALT). Each sample gets a cell: AF:depth for a call, weak (some reads, below the calling thresholds), ref (covered, no such reads), low (too little coverage), unknown (no coverage data) or other (a different ALT at that position).
  • With a parent, each other sample gets a status: new, inherited, lost or unknown. A variant is never new when the parent has some reads for it, and never lost when the sample has some. lost is a lead, not proof: it rests on a 1 kb window mean, not on the depth at the site.
  • All samples must use the same settings. The window size is 1 kb. The thresholds for "covered" and "weak" were not tuned.
  • An imported sample has no reads files, so it cannot run again.
  • The catalog is a record of this page's results. It is not saved in the browser; export it to keep it.

How it works

  • Mapping. Reads are mapped to the reference in WebAssembly, with the Rust aligner rammap (short-read and Nanopore presets).
  • Calling. A built-in haploid caller counts bases at each position and reports SNPs and indels that pass depth, allele-fraction and mapping-quality rules. Long reads can also give large indels (50 bp or more).
  • Effects. Each variant is judged on the transcript with the longest coding sequence of its gene. Introns and UTRs are worked out from the exons and the coding sequence.
  • Output. A VCF, a statistics table (JSON), a genome-wide SVG plot and a locus page for each variant you draw.

Limits

  • Accuracy was measured on simulated reads, which are cleaner than real reads. Repeats and systematic errors in real data can give false calls. Check important variants by eye or with a second method. Results are on the project page.
  • At low coverage (below about 10x) the default depth rule misses many variants.
  • Short reads cannot show large insertions. Large indels are called from long reads only.
  • In the browser, a read pair is mapped as two separate reads. The command-line tool can map pairs.
  • Only Firefox was tested. Chrome and Safari were not. Large data sets need several GB of memory.
  • The tool is for one haploid sample. It is not a diploid or population caller.
  • Gene effects use one transcript per gene (the one with the longest coding sequence).

Command line

The same code runs as a command-line tool. It can also fetch FungiDB genomes with your own API key.

qmutfind call --reference ref.fa.gz --reads r1.fastq.gz --reads2 r2.fastq.gz \
              --sample mutant1 --preset short --out mutant1.vcf
qmutfind annotate --vcf mutant1.vcf --reference ref.fa.gz --gff genes.gff3.gz --out mutant1.annot.vcf
